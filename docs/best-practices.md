# quorb 悬浮球开发踩坑记录 · 最佳实践

> 来源：2026-10 排查「自检卡住 / 球消失 / 点击无响应 / 气泡错位与遮挡」系列问题的复盘。
> 每条按「症状 → 根因 → 规则」组织，规则部分可直接当作 code review 检查项。

---

## 1. 渲染函数定义了但启动时没调用

- **症状**：设置页「健康自检」永远停在「读取中…」，等多久都不会变。
- **根因**：`renderDiag()` 只在某个冷门交互里被调用，页面加载序列漏掉了它。消息从未发出，不是后台慢。
- **规则**：
  - 「XX 一直加载中」先确认**请求到底发没发**，再查网络/后台；
  - 启动序列里需要渲染的卡片，和初始化调用放在一起写，避免「函数存在 ≠ 会被执行」的错觉。

## 2. 初始化崩溃被静默 catch 吞掉，UI 整体不挂载

- **症状**：所有页面都没有悬浮球，而设置页自检全绿（后台链路完全正常）。
- **根因**：启动 IIFE 在 `mountUI()` 之前就访问了尚未创建的 DOM 节点（`orbSlot`），抛 `TypeError`，被外层 `try/catch { console.info(...) }` 吞掉，后续挂载全部跳过。触发条件只是一个状态位（`savedDocked`），所以「以前好使、现在莫名没了」。
- **规则**：
  - **启动序列里禁止在节点创建前碰 DOM**；只操作纯状态（state），DOM 副作用放到节点存在之后；
  - 全局 catch 吞掉的应当只是「收尾失败」，不是「初始化中断」——初始化失败至少要 `console.error` 并留下可 grep 的前缀（本项目统一 `[quorb]`）；
  - 排查这类问题时，第一件事就是看页面 Console 有没有 `[quorb] init failed`。

## 3. 同一个 UI 元素存在两套实现，互相打架

- **症状**：悬停球体弹出一个**空的**灰白胶囊（真气泡带文案但永远隐藏）。
- **根因**：重构后气泡内嵌进了球槽（带文案），但旧的独立空气泡和它的悬停监听没删，监听点亮的还是空的那个。
- **规则**：
  - 重构 UI 时**先删旧实现再加新实现**，grep 确认旧引用清零（本例 `tipEl` 应查到 0 处）；
  - 同一视觉元素只允许一个渲染来源。

## 4. `chrome.sidePanel.open()` 的 user gesture：任何 await 都会杀掉手势

- **症状**：消息能到后台、无报错爆栈，但点击就是没反应（`open()` 被浏览器拒绝）。
- **根因**：SW 消息处理器里先 `await chrome.storage.session.get(...)` 读状态、再调 `open()`。手势随消息送达，但**第一个 await 之后即失效**。
- **规则**：
  - `sidePanel.open()` / `action.openPopup` 这类手势敏感 API，必须是处理器里**第一个**（或与其它调用同一同步任务内）发起的调用；
  - 决策所需状态改为**内存缓存同步读取**（storage 只做镜像写入），保证决策路径零 await；
  - 缓存丢失的代价要设计成「无害的幂等操作」（如对已打开的 panel 重复 open）。

## 5. 鼠标手势靠 mousedown：`pointerup` + `preventDefault(pointerdown)` 会双杀

- **症状**：修完 #4 仍无响应。
- **根因**：点击逻辑挂在 `pointerup` 上，且 `pointerdown` 里 `e.preventDefault()`。规范里鼠标的 transient activation 由 **mousedown** 产生（`pointerup` 只对触摸/笔有效），而 `preventDefault(pointerdown)` 恰好抑制兼容的 mousedown——两条手势路径同时断掉。双击停靠（dblclick）也是同因失效。
- **规则**：
  - **开关类动作用原生 `click` 事件**承载；拖拽才用 pointer 事件；
  - `pointerdown` 尽量不 `preventDefault`，防误选/防原生拖影交给 CSS（`user-select:none; -webkit-user-drag:none`）;
  - 拖拽结束用标志位（如 `suppressClick`）抑制误触 click，而不是靠阻止事件本身。

## 6. `will-change: transform` 的容器是内部 `fixed` 元素的包含块

- **症状**：hover 气泡出现在离球很远的坐标（球在左上、气泡在右下）。
- **根因**：`.q-orb-slot` 带 `will-change:transform`，按规范成为其内部 `position:fixed` 气泡的**包含块**。代码却用 `getBoundingClientRect()`（视口坐标）写入气泡 `left/top`——视口坐标被叠加到球的坐标上。
- **规则**：
  - 给 fixed/absolute 子元素写坐标前，先确认**它的包含块到底是谁**（`transform` / `will-change` / `filter` / `backdrop-filter` 都会改包含块）；
  - 安全线：**CSS 用容器内坐标锚定（如 `left:28px; top:-10px`），JS 只切状态类，不写视口坐标**。附带好处是气泡自动跟随球移动；
  - `getBoundingClientRect()` 用于**读**测量永远合法，出错的是把视口坐标**写**进错误的坐标系。

## 7. 带过渡动画的元素：测量前先禁动画 + 强制回流

- **症状**：边界自适应逻辑写好了，第一次 hover 正常、反复 hover 仍被屏幕边缘裁剪。
- **根因**：清空内联 `transform` 会触发 160ms 补间动画，`getBoundingClientRect()` 读到的是**动画中途值**，用过渡位置算出的修正量必然是错的。
- **规则**：
  - 「清除样式 → 测量 → 写新值」三步之间必须：临时禁用相关属性的 transition → `void el.offsetWidth` 强制回流 → 测量 → 恢复 transition；
  - 症状特征「首次正常、重复出错」基本就是测量撞上动画，直接按此排查。

## 8. fixed 定位元素对视口变化零感知，需要统一的 resize 纠正

- **症状**：打开 Chrome 侧边栏后球被覆盖；窗口缩放、DevTools 停靠同理。
- **根因**：球是 `position:fixed`，不随文档流重排，视口变窄后旧坐标出界；停靠基准点（按旧 `innerWidth` 算）同样过期。
- **规则**：
  - 所有「游离于文档流之外的 UI」都要挂一个**统一的** `resize` 纠正器（防抖 ~120ms），按类型分流处理：
    - 停靠态 → 按新视口重新计算贴边点；
    - 自由态 → clamp 回界内；
    - 展开中的浮层 → 重新定位；
  - 举一反三的判断标准：**凡是坐标依赖 `innerWidth/innerHeight` 的状态，视口变化后全部过期**。

## 通用教训

1. **「静默失败」是这一串 bug 的共同放大器**：`catch {}` + `console.info` 让初始化崩溃、手势拒绝都变成「安静地没反应」。约定统一日志前缀（`[quorb]`），失败必须可观测。
2. **排查顺序**：先确认「事件/消息发没发」（发了吗）→ 再看「对面收到没」（SW 日志）→ 最后才是逻辑对错。本系列三次误判都源于跳过第一步。
3. **MV3 手势三件套**：`click` 事件承载 → SW 处理器同步决策（零 await）→ 手势敏感 API 最先发起。三者缺一即「点击无响应」。
4. **改 CSS 前想包含块，改坐标前想坐标系**，读测量（rect）合法、写坐标（left/top）必须用包含块自己的坐标系。
5. **修一个 UI bug 时顺带查同类**：状态位恢复（#2）、双实现（#3）、双击（#5）都是排查 A 问题时暴露的潜伏 B 问题。

## v2 架构期（P0–P3 多连接改造）新增

## 9. 消息总线上函数会丢：声明式契约必须可序列化

- **症状**：向导保存按钮永远点不了 / 校验比后台宽松，但本地直测 provider 一切正常。
- **根因**：`configSchema` 摘要经 `chrome.runtime.sendMessage` 下发时走结构化克隆，`validate(v)` 这类函数字段会被**静默剥掉**；向导拿到的 schema 与源码里的不是同一个对象。
- **规则**：
  - 跨消息总线的描述符，校验约束用**可序列化字段**表达（`required` / `minLength` / `placeholder`），函数只留在 SW 侧兜底（`validateConfig` 两者都认）；
  - 需要跨总线的数据（如控制台链接）挂在数据结构上（segment 选项带 `consoleUrl`），不要依赖函数计算；
  - 契约测试要加一条「JSON 序列化往返后约束仍在」的断言（contract.test / harness 均有）。

## 10. `chrome.storage.get` 对象形式是「缺省值」语义，测试桩必须实现

- **症状**：产品代码在真机正常，node 冒烟里 `getSnapRaw` 无故返回「该连接还没有快照」。
- **根因**：`get({ key: defaultValue })` 的语义是**读取存储值，缺失时返回默认值**；测试桩把传入对象直接当返回值原样吐回，永远读不到已存数据。
- **规则**：
  - 桩的三种形态都要实现：字符串键、键数组、`{键: 默认值}` 对象；
  - 「只有测试挂、真机没事」先怀疑桩的 API 语义，再怀疑产品代码。

## 11. 周期性重渲染 vs 输入进行中：草稿放 state，重渲染跳过编辑视图

- **症状**：向导里正打字，输入框内容/焦点周期性丢失。
- **根因**：面板有 30s 自动重渲染（让倒计时/状态保鲜），`innerHTML` 全量替换会砸掉正在编辑的输入框。
- **规则**：
  - 输入草稿持久在 state（`state.wizard.values`，input 事件同步），重渲染后可完整恢复；
  - 自动重渲染**跳过编辑视图**（`subView === 'wizard'` 不刷），编辑视图只由自身事件驱动重绘；
  - 任何「定时全量重绘」的组件都要回答：用户正在输入时会发生什么。

## 12. `node --check` 不校验命名导入绑定，语法绿 ≠ 运行绿

- **症状**：`npm run check` 全绿，运行时 `ReferenceError: delSnap is not defined`（P2 冒烟抓到）。
- **根因**：`--check` 只做语法解析，不解析模块导出绑定；漏 import 只有执行到才爆。
- **规则**：
  - 每条消息路径至少有一条执行到最小单元的测试或冒烟（本项目：connections 全 CRUD 有单测/冒烟）；
  - code review 时对「重写文件的 import 块」做一次对照检查：函数体内每个外部名字都要能在 import 里找到。

## 13. 跨版本删除存储键要有版本闸门

- **背景**：v1→v2 迁移按 §4.2 保留旧键一个版本作为回滚窗口，0.6 起清理。
- **规则**：
  - 迁移时记录 `meta.migratedAt = 扩展版本`；清理条件 = schema 已是目标版本 **且** 迁移版本 ≠ 当前版本（缺 migratedAt 视为更早版本完成，同样可清）；
  - 删数据类逻辑永远写成「带条件的幂等函数 + 单独测试」，不要内联在安装钩子里顺手删。
