# quorb 界面设计规范 v0.2 · Liquid Glass

> 一颗悬浮玻璃球，看尽所有 AI 用量。本规范是 `quorb-ui-design.html`（可交互设计稿）的文字版，
> 两者共同构成界面设计的唯一事实来源。v0.2 相对 v0.1 的变化：**整体转向液态玻璃材质**，
> 玻璃改为清透（Clear）/ 暮色（Dusk）双形态，去除深色仪表盘式的视觉语言。

---

## 1. 产品定位与设计原则

- **产品**：Chrome MV3 扩展，聚合追踪各家 LLM 服务（OpenAI / Claude / Gemini / Cursor / Kimi / DeepSeek…）的积分余量、调用量与重置节奏。
- **形态**：常驻悬浮球（Orb）+ 按需展开的详情面板（Panel）。
- **设计原则**：
  1. **一眼可读** — 球体在 1 秒内传达「余量 + 健康度」；
  2. **玻璃是清透的，不是黑色的** — 材质提亮页面而非压暗页面，靠模糊 + 提饱和折射背后内容；
  3. **意图分离** — 拖动是显式意图，点击是查询意图，以 6px 位移阈值区分；
  4. **色彩克制** — 品牌青只出现在数据通道（环 / 高亮 / 图表 / 主按钮），永不与页面争夺注意力。

## 2. 液态玻璃配方（核心）

所有浮层共用同一套材质逻辑，两种形态：

| | Clear（默认，亮/彩页） | Dusk（深色页） |
|---|---|---|
| 底盘 | `linear-gradient(140deg, rgba(255,255,255,.66), rgba(255,255,255,.34) 48%, rgba(255,255,255,.48))` | `oklch(38→24% 0.02 260 / .72–.8)` |
| 滤镜 | `blur(22px) saturate(1.8) brightness(1.04)` | `blur(6px) saturate(1.5) brightness(.9)`（球体 blur(4px)） |
| 高光棱线 | `inset 0 1px 1px rgba(255,255,255,.9)` | `inset 0 1px 1px rgba(255,255,255,.34)` |
| 折射缝 | `inset 0 0 0 1px rgba(255,255,255,.32)` | `inset 0 0 0 1px rgba(255,255,255,.16)` |
| 柔影 | `0 24px 60px -18px oklch(32% 0.05 255/.3)` | `0 36px 90px -20px rgba(5,8,20,.65)` |
| 文字 | 墨色 `oklch(24% 0.02 255/.88)` + 白色 1px 底光 | 白 `rgba(255,255,255,.94)` + 深色投影 |
| 切换 | 注入时采样页面亮度自动选择，切换带 260ms 交叉淡化 | |

**三层必备细节**（缺一即「塑料感」）：

1. **边缘色散折射缝**：1px mask 边框，渐变 `白 → 粉 oklch(78% 0.09 340) → 蓝 oklch(80% 0.07 230) → 白`，模拟玻璃边缘的色散；
2. **顶部高光棱线**：inset 白色 1px 高光 + 球体左上一枚锐利小高光点（径向渐变 + rotate -26°）；
3. **镜面扫光**：悬停时一道 112° 白色光带横扫而过（1s ease-out，仅 hover 触发）。

**玻璃要有东西可折射**：演示与文档中的场景是缓慢流动的极光壁纸（4 枚大光斑 blur(52px)、16–24s 交替漂移）；
真实页面本身就是「内容」，无需任何背景处理。

## 3. 色板（OKLCH）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--acc` | `oklch(52% 0.115 205)` 冰海青 | 进度环、高亮、主按钮、链接、吸附光带 |
| `--acc-2` | `oklch(72% 0.085 190)` | 环渐变末端 |
| `--warn` | `oklch(72% 0.135 75)` | 余量 21–45%、同步提示 |
| `--crit` | `oklch(60% 0.19 22)` | 余量 ≤ 20%、授权异常 |
| 球体状态透光 | `--glow`（青/琥珀/珊瑚，径向置于球体底部） | 环色在玻璃内的「透光」 |
| 服务色 | OpenAI `64% 0.11 175` · Claude `66% 0.12 50` · Gemini `62% 0.12 260` · Cursor `58% 0.02 90` · Kimi `64% 0.15 330` · DeepSeek `56% 0.14 275` | 芯片 / 分段条 / 趋势图（芯片叠加顶部高光做玻璃珠化） |

**字体**：system-ui（SF / PingFang）为唯一 UI 字体；数字 `font-variant-numeric: tabular-nums`；
标题 -2.8% 字距；生产包零外部字体。设计稿排版用 Instrument Serif Italic 做点睛（仅设计稿，不入生产）。

**圆角 / 阴影**：6 / 12 / 16 / 20 / 24 / 30，球与面板 24–30；阴影一律三层（大柔影 + 近影 + 内侧高光棱线）。

## 4. 球体（Orb）

56×56px（紧凑 44）。层次自上而下：清透玻璃底盘（含锐利高光点）→ SVG 环（r=25，线宽 3，
`drop-shadow(0 0 5px 环色/.55)` 微光）→ 球心数字 → sheen 扫光层 → 徽标。

环色：`>45%` 青→青绿渐变 · `21–45%` 琥珀 · `≤20%` 珊瑚 + 呼吸光晕（唯一常驻循环动画）；
未连接：虚线环 + 折线图标。聚合口径 = 配额型服务剩余之和 ÷ 配额总额；余额型不参与；
**多窗口服务（如 GLM 的 5 小时 + 周配量）取「最紧窗口」百分比参与聚合与警示**（见 5.1）。

## 5. 详情面板（Panel）

- 348px 宽，圆角 26，Clear/Dusk 跟随球体材质；
- 结构：面板头（圆形玻璃按钮）→ 聚合 Hero（40px 数字 + 绝对值 + 配额占比分段条）→
  iOS 式分段页签（总览/趋势/设置）→ 服务明细行（玻璃珠芯片 + 64px 迷你条，可展开详情）→ 同步脚注；
- 从球体位置缩放展开（transform-origin 指向球心，@starting-style 防闪烁），越界自动翻转；
- Esc / 点击外部 / 再点球体收起；
- 脚注「管理服务 →」进入二级视图（见第 6 节）。

### 5.1 多窗口配额（GLM：5 小时窗口 + 周用量）

一个服务可能同时有多个时间窗（5 小时滚动窗口、周配量，未来可能有月配额）。展示遵循 **「最紧窗口」min 规则**：

1. **球心 / 聚合 / 警示色**：该服务只贡献 `min(各窗口余量%)` —— 限制你的是什么，就显示什么；
2. **明细行收起态**：进度条 = 最紧窗口百分比；次行标注「双窗口 · 最紧 5h · 2h 14m 后重置」；
3. **明细行展开态**：双窗卡并排，每张显示 余量/上限/百分比/重置；最紧的一张琥珀描边 + 「最紧」标，并注明「决定当前可用量」；
4. **重置语义分两种**：
   - 滚动窗口 → **倒计时**：「2h 14m 后重置」（每分钟更新）；
   - 固定周期 → **时点**：「周一 00:00 · 3 天」；
5. **聚合区提示**：当某服务的最紧窗口 ≤45% 时，Hero 分段条下方出现琥珀提示
   「最紧窗口：GLM 5 小时 26% · 2h 14m 后重置，聚合已按它计算」，解释聚合数字为何偏低。

## 6. 连接服务与密钥管理

### 6.1 入口与流程

入口有两处：空状态 CTA「＋ 添加服务」；面板脚注「管理服务 →」。

```
管理服务（列表） ──添加/编辑──▶ 连接向导 ──验证并保存──▶ 回列表（新行闪绿）
     ▲                              │
     └────────── 返回 ──────────────┘
```

1. **管理服务**（二级视图）：每行 = 服务芯片 + 连接状态（绿点/灰点）+ 打码密钥
   `sk-proj-••••7f2a` + 编辑/删除；未连接行显示「＋ 添加」。头部计数「已连接 2 / 6」。
2. **连接向导**：服务胶囊选择器（已连接带 ✓）→ API Key 输入框
   （`type=password` 打码、粘贴按钮、显隐切换）→ 实时格式提示 →
   「高级」折叠区可填自定义接口地址（代理/中转）→ **验证并保存**。
3. **验证中**：按钮转 spinner「正在验证…」，提示行说明正在与官方接口核对；期间不可重复提交。
4. **已保存**：返回列表，新行闪绿一次；密钥即刻变为打码形态。
5. **失败**（401）：输入框红描边 + 抖动一次，提示「密钥无效或已被撤销」，可重试。

### 6.2 密钥的安全边界（写进 UI 的承诺）

- 仅保存在本机 `chrome.storage.local`；**绝不使用 storage.sync**（密钥不漫游、不进云备份）；
- 界面中永远只出现打码形式，明文仅在输入框存在的瞬间可见；显隐切换是唯一例外；
- 用量请求只发往各服务官方域名（或用户显式填写的自定义地址）；
- 「管理服务」中可随时删除，删除即销毁；移除扩展即全部销毁；
- 向导与列表底部固定展示上述要点（锁图标 + 列表），作为信任声明。

## 7. 交互与手势

拖动（>6px 判定）→ 边缘 ≤20px 磁吸（光带确认）→ 停靠没入 52%、悬停滑出 72%；
单击展开面板；双击悬浮↔停靠切换；位置记忆 `chrome.storage.sync`（全局/按站点）；
球体 `role=button` + aria-label 随数据更新；窗口 resize 后二次收敛。

## 8. 动效预算（GPU: transform / opacity / filter）

| 场景 | 时长 · 缓动 |
|---|---|
| 球体悬停（scale 1.07）+ 镜面扫光 | 180ms ease-out / 扫光 1s |
| 环数值变化（dashoffset） | 600ms ease-out |
| 面板展开 / 收起 | 260ms spring |
| 磁吸停靠 | 400ms spring |
| 同步扫掠 | 1.1s linear ∞ |
| 危急呼吸 | 2.2s ease-out ∞（仅 ≤20%） |
| 明细行展开 | 260ms spring |
| 壁纸流影 | 16–24s alternate ∞（仅设计稿场景） |

同屏并发 ≤ 3；`prefers-reduced-motion` 全部退化为直接切换。

## 9. 实现注意（工程衔接）

1. Content Script 建单个 Shadow DOM（closed）挂载球体 + 面板；本配方即 Shadow 内样式；
2. `backdrop-filter` 需要元素背后确有页面内容——球体永不加不透明底；
3. 材质自适应：注入时对根节点采样亮度（或读取 `prefers-color-scheme` + 页面 meta），一次判定不随滚动切换；
4. **密钥存储**：`chrome.storage.local` 仅存密钥与配置；写入前不做明文持久化到任何日志；可选用一枚设备内随机口令做 AES-GCM 加密后落盘（v0.3 增强）；
5. **多窗口数据结构**：每服务 `windows[]`（`{kind:'rolling'|'fixed', limit, used, resetAt}`），binding = 余量最小者；滚动窗口倒计时由 service worker 每分钟推送一次，避免每个页面各自起定时器；
6. 全部动画 GPU 属性；面板未打开不渲染明细 DOM；PDF/商城等受限页跳过注入；
7. 后续：官方 SVG 单色图标玻璃珠化、阈值自定义、用量告警通知。
